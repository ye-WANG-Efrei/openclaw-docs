## How Skills Work

A skill packages procedural guidance and optional reusable assets so an agent does not have to rediscover the workflow every time. In practice, a good skill turns repeated operator knowledge into a reviewable, versioned artifact.

## Installing Existing Skills

Potential sources include:

- OpenHub
- GitHub repositories
- an internal or public skill registry

A safe install workflow is:

1. inspect the skill description and trigger conditions
2. read `SKILL.md`
3. inspect bundled scripts and references
4. verify the skill does not assume unsafe tool access
5. install it into the approved skill directory

## Skill Safety Review

Before approving an external skill, check:

- which tools it expects to use
- whether it writes files or touches networks
- whether bundled scripts are deterministic and understandable
- whether the instructions encourage overbroad permissions
- whether the references contain stale or vendor-specific assumptions

## Creating Your Own Skills

A practical authoring workflow looks like this:

1. define the requirement
2. design inputs and outputs
3. generate the skeleton
4. implement scripts, references, and assets
5. test the skill on realistic requests

## Recommended Skill Folder Shape

```text
my-skill/
??? SKILL.md
??? agents/
?   ??? openai.yaml
??? scripts/
??? references/
??? assets/
```

## What Makes A Good Skill

- narrow trigger conditions
- clear execution flow
- minimal but high-value reference material
- deterministic helpers when repeated code would otherwise be rewritten
- explicit validation expectations
