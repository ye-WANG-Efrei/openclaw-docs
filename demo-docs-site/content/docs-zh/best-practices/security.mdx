## 常见风险

| 风险 | 可能后果 | 缓解方式 |
| --- | --- | --- |
| 工具权限误用 | Agent 拥有超出需要的读写或执行能力 | 默认拒绝、最小权限、显式批准 |
| API Key 泄露 | 密钥出现在日志、prompt 或仓库文件中 | 密钥管理、脱敏与轮换 |
| Gateway 暴露 | 网关成为薄弱点，泄露流量与凭证 | 认证、隔离、环境分层 |
| Prompt 注入 | 外部内容诱导模型做危险动作 | 工具门控、来源分级、输出审查 |
| 记忆污染 | 错误摘要进入长期上下文 | 记忆校验与保留审查 |

## 安全基线

- 高风险工具默认关闭
- 开发与生产密钥分离
- 记录敏感操作，但不记录敏感值
- 外部 Skill 和脚本必须经过审查
- 把检索到的网页或用户内容视为不可信输入

## Prompt 注入不能只靠 Prompt 解决

要用结构化控制来兜底：

- 工具能力要有限制
- 危险动作要二次确认
- 网络访问要分区或受控
- 不可信上下文要和系统指令分层

## Gateway 加固建议

生产级 Gateway 至少应具备：

- 身份认证
- 环境级凭证隔离
- 按路由记录日志
- 配额或限流
- 清晰的回退策略

## 审查清单

- 哪些工具是高风险能力？
- 密钥存在哪里，如何轮换？
- 不可信文档是否会影响工具调用？
- Gateway 是否暴露了过多能力？
