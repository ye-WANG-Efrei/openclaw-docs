## 核心方法

| 方法 | 作用 | 适合场景 |
| --- | --- | --- |
| QMD 检索 | 只取与任务最相关的上下文片段 | 大型知识库 |
| 上下文压缩 | 在进入贵模型前先做摘要 | 多步研究、长文档总结 |
| 模型路由 | 只把高价值步骤送到高成本模型 | 混合成本工作流 |
| 心跳任务 | 用小任务定期检查，而不是大任务全量重扫 | 监控与自动化 |
| 本地索引 | 在本地处理高吞吐或私有语料 | 隐私敏感场景 |

## 实战流程

1. 先检索最可能有用的文档片段
2. 对这些片段做压缩或总结
3. 把压缩后的任务路由给合适模型
4. 只保留真正能帮助未来任务的摘要

## QMD 检索什么时候最值钱

当问题不是“模型不够聪明”，而是“拿到的上下文不对”时，优先提升检索质量。错误的上下文即使交给更强模型，也只会让系统更贵，不一定更准。

## 压缩时应该保留什么

一个好的压缩结果，应该尽量保留：

- 约束条件
- 实体与名称
- 精确数字
- 悬而未决的问题
- 下一步动作

## 检查清单

- 这个任务真的需要这么多上下文吗？
- 有没有每次都重复发送的固定内容？
- 最贵模型是不是只用于关键步骤？
- 摘要是否有原文可追溯？
