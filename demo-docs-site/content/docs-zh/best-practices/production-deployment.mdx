## 生产部署真正要解决什么

生产部署不只是让服务“能启动”。更关键的是让模型路由、工具权限、Gateway 策略和记忆行为都可观察、可回滚、可解释。

## 参考拓扑

```text
Users -> Web or API surface -> OpenClaw app -> Gateway -> Model providers or local runtimes
                                     |
                                     -> logging, traces, metrics, evaluation data
```

## 环境策略

| 环境 | 目的 | 建议规则 |
| --- | --- | --- |
| local | 快速迭代 | 可用 mock 或低成本模型 |
| staging | 发布验证 | 尽量贴近生产路由与权限 |
| production | 承载真实流量 | 最强的观测、审批与回滚能力 |

## 发布检查表

1. 在 staging 验证模型路由与回退
2. 确认工具权限符合本次发布范围
3. 审查 Gateway 凭证与配额
4. 查看延迟、失败率与成本趋势看板
5. 确认配置和路由都可快速回滚

## 至少要观测什么

- 请求量
- 成功率与失败率
- 最终命中的模型与提供方
- token 用量
- 工具调用频率
- Gateway 错误与回退次数

## 回滚原则

模型路由与权限策略要像代码一样可回滚。只要新的模型档位或 Gateway 规则提高了失败率，就应该能在不重发整套应用的前提下快速恢复。

## 最终建议

Agent 系统最容易失去信任的时刻，就是“能力变强了，但可观测性没有跟上”。在生产环境里，优先透明、可控和可逆，而不是盲目追求自治。
