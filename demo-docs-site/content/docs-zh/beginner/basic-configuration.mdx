## 需要优先定下来的配置面

| 配置面 | 第一阶段要决定什么 | 为什么重要 |
| --- | --- | --- |
| 默认模型 | 一个稳定的基础模型档位 | 避免质量随机漂移 |
| 工具策略 | 默认允许还是默认拒绝 | 决定系统安全边界 |
| Skill 目录 | Skill 放在哪里 | 方便发现和审查 |
| 记忆策略 | session、persistent 或混合 | 影响上下文质量与保留风险 |
| 日志策略 | 记录哪些关键信息 | 决定问题是否可定位 |

## 起步配置示例

```json
{
  "defaultModelProfile": "reasoning-default",
  "toolPolicy": "deny-by-default",
  "skillDirectories": ["./skills"],
  "memoryMode": "session",
  "logging": {
    "level": "info",
    "includeModelSelection": true
  }
}
```

## 推荐默认值

- 在系统稳定前，只保留一个默认模型档位
- 对高风险工具采用默认拒绝
- Skill 目录放在版本控制可见的位置
- 先使用会话级记忆，再逐步引入持久化记忆
- 日志里至少能看到模型选择与关键工具调用

## 配置审查问题

在进入复杂路由和生产部署前，先问自己：

- 新同事能否快速看出默认模型是什么？
- 为什么启用了这些工具，能说清楚吗？
- 记忆为什么要持久化，是刻意设计还是默认遗留？
- 一次失败能否通过日志快速回放？

## 常见配置反模式

- 关键默认值散落在太多文件中
- 在没有保留策略之前就开启持久记忆
- 环境变量与硬编码默认值混用，但优先级不明确
