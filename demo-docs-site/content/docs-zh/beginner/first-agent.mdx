## 为什么第一个 Agent 要做得“小而全”

第一个 Agent 的目的不是追求自动化程度，而是验证整条链路：任务输入、模型选择、Skill 触发、工具调用和结果输出都要能看见、能解释。

一个仓库助手、文档助手或支持工程师助手，通常比“全自动代理”更适合作为起点。

## 一个起步配置示意

下面是概念性的配置草图，字段名请替换成你项目里的真实写法：

```yaml
name: repo-helper
goal: 回答仓库问题，并提出安全的实现步骤。
model_profile: reasoning-default
tools:
  - filesystem
  - terminal
skills:
  - openclaw-docsite-generator
memory:
  mode: session
  persist_summary: true
```

真正重要的不是字段名，而是这些决策必须被明确写出来：

- 做什么任务
- 用什么模型档位
- 哪些工具可用
- 哪些 Skill 会触发
- 什么记忆会被保留

## 搭建步骤

1. 先把目标收窄。
   例如：总结当前仓库并给出下一步开发建议。
2. 只选一个默认模型档位。
   在系统稳定之前，不要先上复杂路由。
3. 收紧工具边界。
   只启用任务真正需要的能力。
4. 绑定一个 Skill。
   让 Agent 拥有过程知识，而不是每次重新摸索。

## 如何验证它已经可用

一次成功的首个 Agent 运行，至少应该满足：

- 日志里能看到实际选中的模型
- Skill 在相关任务下被触发
- 工具调用可解释、可追踪
- 输出结果对人类是有用的，而不是纯“看起来聪明”

## 示例测试提示词

```text
请总结当前工作区，识别主要项目目标，并提出接下来三个最值得做的实现任务。
```

## 常见误区

- 一开始就追求强自治，而不是先验证安全边界
- 给第一个 Agent 太多工具和模型选择
- 只看最终回答，不看中间日志和权限行为
