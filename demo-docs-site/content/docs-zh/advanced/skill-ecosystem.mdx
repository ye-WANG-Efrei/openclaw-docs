## Skill 的作用

Skill 的本质是把“重复出现的过程知识”打包成可复用资产。这样 Agent 不必每次从零摸索流程，而是可以沿着已经沉淀好的路径执行任务。

对团队来说，Skill 也是一种工程化文档：它说明了什么时候触发、怎么执行、依赖哪些脚本和参考资料。

## 安装现有 Skill

常见来源包括：

- OpenHub
- GitHub 仓库
- 内部或公开的 Skill Registry

一个安全的安装流程通常是：

1. 看描述与触发条件
2. 通读 `SKILL.md`
3. 检查 scripts、references、assets
4. 确认它没有默认要求过宽的工具权限
5. 安装到批准的 Skill 目录中

## 安全审查重点

- 这个 Skill 预期调用哪些工具？
- 是否会写文件、联网或执行脚本？
- 脚本是否足够可理解、可复查？
- 指令里有没有鼓励过宽权限？
- 参考资料是否包含过时假设？

## 自己编写 Skill 的流程

1. 定义需求
2. 设计输入与输出
3. 生成骨架
4. 实现脚本、参考资料与资源
5. 用真实请求验证 Skill

## 推荐目录结构

```text
my-skill/
├── SKILL.md
├── agents/
│   └── openai.yaml
├── scripts/
├── references/
└── assets/
```

## 好 Skill 的特征

- 触发条件明确
- 执行流程清楚
- 参考资料少而精
- 重复代码用脚本固化
- 有明确验证方式
