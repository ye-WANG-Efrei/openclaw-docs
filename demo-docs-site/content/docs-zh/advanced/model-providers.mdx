## 两类接入路径

### 官方 API

OpenAI、Anthropic 等官方 API 往往拥有最直接的功能支持路径、文档语义和计费透明度。

### 聚合层

像 OpenRouter 这样的聚合层，适合在实验期快速接多个模型家族，用一个入口完成比对和路由。

## 取舍对比

| 接入方式 | 优势 | 代价 | 更适合 |
| --- | --- | --- | --- |
| 官方 API | 支持路径清晰、原生能力完整、抽象层更少 | 需要管理多组密钥和接入代码 | 稳定生产路径 |
| 聚合层 | 实验快、模型选择广、便于统一入口 | 增加一层依赖，部分语义与原生能力会被抽象 | 多模型评估与快速试验 |

## 选择建议

优先用官方 API 的情况：

- 需要厂商原生特性
- 生产环境希望减少中间层
- 合规或采购要求直接与厂商对接

适合先上聚合层的情况：

- 需要同时比较很多模型
- 希望一个入口快速完成实验
- 想在正式收敛前保留多提供方灵活性

## 示例配置

```env
OPENAI_API_KEY=<official-openai-key>

```

```env

OPENROUTER_BASE_URL=<aggregator-base-url>
```
