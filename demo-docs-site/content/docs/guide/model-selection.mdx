## 3. Recommended Models by Cost

Many people care most about **pricing / free tier**.
Based on real-world usage, model choices can be grouped into three categories: **free trials, low-cost models, and high-performance models (best value)**.

---

Many platforms offer a free tier or a pool of free models — ideal for learning, testing projects, or building small tools.

**Best for:**

- Small tool projects

If you are working on **personal projects or small-scale Agents**, prioritize low-cost models.

| Model | Characteristics |
|---|---|

## Routing Heuristics

Start with simple rules before building anything complex:

- For code rewriting or repository analysis, prioritize coder-tier models
- When reading large amounts of material, prioritize long-context or strong-summarization models
- For periodic automation tasks, prioritize the smallest model that meets the quality threshold
- When private data cannot leave your boundary, prioritize local or privately deployed models

## Example Policy

```yaml
routes:
  - when: task_type == "coding"
    use: coder-primary
  - when: task_type == "research"
    use: research-primary
  - when: task_type == "automation"
    use: low-cost-runner
  - when: task_type == "private-indexing"
    use: local-context-model
fallback: reasoning-default
```

## Measure First, Then Scale Models

Before introducing more models, at minimum track:

- Task success rate
- Average latency
- Average token cost
- Human rework rate
- Failure rate by task type

## Common Anti-Patterns

- Running all tasks on the single most expensive model
- Adding more providers before properly measuring the current routing strategy
- Selecting models based on popularity rather than task evidence
