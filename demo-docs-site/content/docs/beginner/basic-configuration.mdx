## Configuration Surfaces To Define Early

| Surface | What to decide first | Why it matters |
| --- | --- | --- |
| Model default | one reliable baseline model | Prevents random quality shifts |
| Tool policy | default allow or deny posture | Reduces accidental privilege creep |
| Skill lookup | where reusable skills live | Keeps workflows discoverable |
| Memory policy | session, persistent, or hybrid | Controls context quality and retention risk |
| Logging | info level, traces, request ids | Makes failures diagnosable |

## Starter Configuration Example

Use a project-local config file or environment-backed config, depending on the real OpenClaw runtime.

```json
{
  "defaultModelProfile": "reasoning-default",
  "toolPolicy": "deny-by-default",
  "skillDirectories": ["./skills"],
  "memoryMode": "session",
  "logging": {
    "level": "info",
    "includeModelSelection": true
  }
}
```

## Recommended Beginner Defaults

- Keep one default model profile until the system is stable.
- Prefer deny-by-default for powerful tools.
- Store skills in a predictable folder that can be reviewed in version control.
- Use session memory first, then add persistence only when you know what must survive.

## Configuration Review Questions

Ask these before moving into advanced architecture work:

- Can a new teammate identify the default model and provider quickly?
- Can you explain why each tool is enabled?
- Is memory retention intentional, or just left on by default?
- Can you trace why a specific answer was produced?

## Common Misconfiguration Patterns

- Hiding critical defaults across too many files.
- Enabling persistent memory before retention rules exist.
- Mixing environment variables and hard-coded defaults with no clear precedence.
