## Provider Categories

### Official APIs

Official providers such as OpenAI and Anthropic usually give you the most direct path to documentation, rate-limit clarity, and provider-specific features.

### Aggregators

Aggregation layers such as OpenRouter can simplify multi-provider experiments by offering one billing path and one connection surface for many model families.

## Tradeoff Table

| Access path | Advantages | Tradeoffs | Best for |
| --- | --- | --- | --- |
| Official APIs | Clear provider support path, direct feature access, fewer abstraction layers | More keys and more integration work across providers | Stable production paths |
| Aggregators | Faster experimentation, broad model catalog, centralized routing | Added dependency layer and sometimes less direct provider semantics | Evaluation, routing labs, unified experiments |

## Selection Guidance

Choose official APIs when:

- you need provider-native features
- you want fewer abstraction layers in production
- procurement and support require direct vendor relationships

Choose an aggregator when:

- you are comparing many models quickly
- you want one endpoint for experiments
- you need a temporary bridge before committing to a narrower provider set

## Review Checklist

- Document which environments may use an aggregator.
- Record which workloads require direct provider access.
- Verify logging preserves the final provider and model choice.
